## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Create separate PoorMansPokedex.Core/Endpoints/IPokedexEndpoint.cs and PokedexEndpoint.cs files with the two Task<PokedexEntry> overloads required by the task.
2. Inject IPokeApiHttpClient into PokedexEndpoint. Build relative pokemon/{name} and pokemon/{id} paths safely, call the wrapper asynchronously, dispose each returned HttpResponseMessage, and deserialize its content stream with System.Text.Json using async/await and no ConfigureAwait. Surface a null JSON result explicitly rather than returning a null value through the non-nullable contract.
3. Add an IPokedexEndpoint getter to IPokeApiService and expose its implementation on PokeApiService. Preserve the existing HttpClient constructor; instantiate PokeApiHttpClient with the injected HttpClient and construct/assign PokedexEndpoint in the service constructor.
4. Keep changes focused on the two endpoint files and the existing service interface/implementation, leaving other uncommitted files untouched.
5. Validate with a solution build and a focused HTTP-wrapper smoke test for both name and id paths, successful PokedexEntry deserialization, and propagation of HTTP/JSON failures.
