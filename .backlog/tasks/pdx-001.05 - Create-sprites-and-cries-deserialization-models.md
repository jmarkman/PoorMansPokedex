## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In PoorMansPokedex.Core/Models, add the classes for the sprites and cries objects of the pokemon payload (https://pokeapi.co/api/v2/pokemon/magnemite). sprites.versions and sprites.other.official-artwork.versions are structurally inconsistent across generations/games (extra fields like transparent/gray variants in older generations, optional nested animated or icons sub-objects), so per your decision they are modeled generation-by-generation rather than one class per game/variant.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A Cries class represents the cries object (Latest string, Legacy string)
- [ ] #2 A Sprites class represents the sprites object top-level string fields (BackDefault, BackFemale, BackShiny, BackShinyFemale, FrontDefault, FrontFemale, FrontShiny, FrontShinyFemale), plus an Other property and a Versions property
- [ ] #3 An Other class represents sprites.other (DreamWorld, Home, OfficialArtwork, Showdown properties)
- [ ] #4 DreamWorld (FrontDefault, FrontFemale), Home (FrontDefault, FrontShiny, FrontFemale, FrontShinyFemale), and Showdown (same 8 front/back fields as the root Sprites class) classes exist for their respective sprites.other entries
- [ ] #5 An OfficialArtwork class represents sprites.other.official-artwork (FrontDefault, FrontShiny strings, plus a Versions property using the same generation-only representation described below, since official-artwork has its own nested versions tree)
- [ ] #6 A GenerationSprites class represents a versions tree (used for both sprites.versions and sprites.other.official-artwork.versions) with eight properties, Generation1 through Generation8, mapped to the JSON keys generation-i through generation-viii; Roman numerals are converted to integers in these class/property names per your naming rule
- [ ] #7 Each of the eight Generation1..Generation8 classes captures its per-game contents loosely (e.g. a Dictionary<string, JsonElement> property, or a [JsonExtensionData] member) instead of one fixed class per game/variant, since that inner shape varies per generation and per Pokemon
- [ ] #8 Each class lives in its own file in Models per architecture.instructions.md
- [ ] #9 Solution builds successfully
<!-- AC:END -->
