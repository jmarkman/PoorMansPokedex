## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In PoorMansPokedex.Test, create a MockingTools folder containing reusable test data builders: (1) one or more builder/factory helpers that construct different variations of the PokedexEntry deserialization class (e.g. a fully populated entry, a minimal entry, entries with empty/null collections) so unit tests do not hand-roll PokedexEntry graphs inline; (2) a helper that, given canned HttpResponseMessage(s), produces an HttpClient backed by a mocked HttpMessageHandler using Moq, following the approach described at https://gingter.org/2018/07/26/how-to-mock-httpclient-in-your-net-c-unit-tests/ (mock the protected SendAsync method of HttpMessageHandler and construct HttpClient from that mock handler). Depends on the PoorMansPokedex.Test project existing and on PokedexEntry being complete.
<!-- SECTION:DESCRIPTION:END -->
