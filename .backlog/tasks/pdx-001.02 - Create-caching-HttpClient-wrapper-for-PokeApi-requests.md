## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In PoorMansPokedex.Core, create a class that wraps the HttpClient supplied to PokeApiService, out of respect for the educational PokeApi's request to avoid hammering their servers. This wrapper exposes a method that wraps HttpClient.GetAsync with basic exception handling driven by checking HttpResponseMessage.StatusCode (e.g. throwing or returning a typed error result on non-success codes, rather than letting raw HttpRequestExceptions propagate unexamined). It implements rudimentary in-memory caching so that a duplicate request (same request URI) is served from the cache instead of re-hitting the API, and it exposes a way for callers to explicitly bypass the cache to force a fresh call to the API. Give this wrapper its own interface in a separate file, consistent with other services in this codebase. Assume the HttpClient's BaseAddress is already set to https://pokeapi.co/api/v2/ by the caller.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add separate ICachingHttpClient.cs and CachingHttpClient.cs files in PoorMansPokedex.Core. Define an asynchronous GET method that accepts a relative request path, optionally bypasses the cache, and returns the raw response body as a string for the later endpoint to deserialize.
2. Keep an in-memory cache of successful response bodies keyed by the resolved request URI. Return a cached body for a repeat request; when bypass is requested, perform a fresh GET and replace the cached value only after a successful response.
3. Inspect each HTTP response status explicitly. For non-success status codes, throw an HttpRequestException that includes the status code and request URI, and do not cache the failed response. Dispose responses and use async APIs consistent with the WPF guidance.
4. Build PoorMansPokedex.Core to verify the wrapper compiles. Leave PokeApiService wiring and wrapper test-fixture work to their dependent tasks.
<!-- SECTION:PLAN:END -->
