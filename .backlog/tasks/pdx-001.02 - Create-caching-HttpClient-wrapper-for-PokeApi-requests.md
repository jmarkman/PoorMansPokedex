## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In PoorMansPokedex.Core, create a class that wraps HttpClient to respect PokeApi maintainers' request for well-behaved clients. It wraps HttpClient.GetAsync with basic status-code-based exception handling and a rudimentary in-memory cache keyed by request URI, with an explicit way for callers to bypass the cache and force a fresh call. Assume the HttpClient passed in already has BaseAddress set to https://pokeapi.co/api/v2/. Give it an interface (e.g. IPokeApiHttpClient) alongside the concrete class so it can later be mocked when unit testing PokedexEndpoint.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A new interface and its implementing class exist as separate files (e.g. IPokeApiHttpClient / PokeApiHttpClient), each accepting an HttpClient via its constructor
- [x] #2 The wrapper exposes an async Get method that wraps HttpClient.GetAsync, checks HttpResponseMessage.StatusCode, and throws or surfaces a clear exception on non-success status codes
- [x] #3 Repeated calls for the same request URI return the cached HttpResponseMessage (or its content) instead of calling HttpClient.GetAsync again
- [x] #4 The Get method exposes a parameter (e.g. a bool bypassCache) that, when set, always calls HttpClient.GetAsync and refreshes the cache instead of reading from it
- [x] #5 Async methods use async/await without ConfigureAwait, per dotnet.instructions.md
- [x] #6 Solution builds successfully
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add IPokeApiHttpClient.cs and PokeApiHttpClient.cs as separate files in PoorMansPokedex.Core. Define the asynchronous request contract on the interface; inject HttpClient into the implementation and retain it in a private readonly field using the project field-naming convention.
2. Implement GetAsync for request URIs relative to the configured BaseAddress, using the resolved URI as the in-memory cache key. Check response status and surface non-success responses as a clear HTTP exception; cache only successful responses.
3. On a normal cache hit, return the cached response data without another network call. On bypass, evict/read past the existing entry, issue a fresh HttpClient.GetAsync request, and refresh the cache on success. Avoid returning one shared disposable HttpResponseMessage instance to multiple callers by caching response data and producing a fresh response for cache hits.
4. Use async/await throughout and do not use ConfigureAwait. Keep the design within the requested simple in-memory wrapper and use the later wrapper test task for explicit status, cache-hit, and bypass coverage.
5. Build the solution and verify the acceptance criteria.
<!-- SECTION:PLAN:END -->
